learnleetcode UI design

The visual language of the journal site: tokens, components, and the two pages. This page is the spec; src/layouts/Base.astro and the page styles implement it. Every mock shows the light and dark theme side by side.

Color · Neutrals

Five neutrals build every surface. Paper is the page, panel is anything raised on it, rule is every border and divider. Ink is body text; muted is secondary text and metadata. Each swatch shows light on the left, dark on the right.

Color · Hues & roles

Four hues hold the values; each has a soft twin for the fill behind it, and the strong hue is the text or edge on top. Code never names a hue. It names a role, and each role maps to one hue. Swatches read light strong, light soft, dark strong, dark soft.

Typography

Two families. Atkinson Hyperlegible sets all prose and UI; it is built to keep look-alike characters apart (0 O, 1 l I). The system monospace sets code, inline and in blocks. Body text is 17px at 1.5 line height; the rest of the ramp is relative to it.

Shape

Every edge is a 1.5px rule. Radius grows with the size of the thing: a chip is barely rounded, a panel is soft. The layout is one column, at most 880px wide with a 20px gutter.

Explainer

An explainer is an animated walkthrough of one solution, stepped by the reader. Its layout is fixed; a problem supplies only the content. Top to bottom:

  • 1Examples — preset inputs, one pressed at a time; the first loads on open.
  • 2Your own input — the problem's fields and a Run button; a rejected input shows its reason in scene-remove.
  • 3Stages — one or more panels, each a title, a subtitle, a scene that scrolls sideways when wide, and an optional footer row of chips.
  • 4Controls — Restart, Back, Play/Pause, Next, and the step counter. Autoplay advances every 2 seconds and stops at the last step. ← → step and Space plays.
  • 5Narration — what this step does, in prose.
  • 6Readout — the variables' values after this step.
  • 7Code highlight — the lines this step runs, marked in the solution's code block below the explainer.

A scene is drawn only from these building blocks (src/explainer/scene.tsx). Each is placed on a column grid: column c sits at 96 + 62·c px, leaving the first 96px for row labels. Changing a block's column or top between steps animates it there.

Rules
  • A color comes from a token. A new need gets a new token here first, then in Base.astro.
  • Code names roles, never hues. A role keeps its one meaning: difficulty roles live on the badge, scene roles inside an explainer.
  • An explainer changes only its scene. Layout, controls, timing and styling belong to the skeleton.
  • The theme follows the reader's system setting. Every change is checked in both themes.
  • Code blocks keep GitHub's syntax colors on the panel fill.
